- 修改边界：先以同一目标接口补 Keychain/CurrentUser DPAPI provider，再实现一个共享 TypeScript Cordis 连接插件；不移植旧 Python Runtime、SQLite Store、Dispatcher、mcporter、全局绑定或企业 Managed Connector Gateway。仅在许可证和官方条款允许时复用第三方代码。
- 切片顺序：OS 凭据 provider → 共享 Host 与 loopback RPC → 目标 Settings UI → 钉钉消息 → 飞书消息 Bot → 微信设备流 → 腾讯文档 credential-aware MCP → 动态业务 Tool/能力卡 → 组合验收。
- 检查：四类连接必须能被用户与 Agent 发现，进入正确连接页并到达真实 provider 授权 handoff；secret 不经 describe/RPC/log/Tool/config dump 返回。2.0.7 的发布验收在提交 OAuth consent、二维码扫码确认、凭据或外部写入前停止；飞书文档/Drive、微信 iLink、腾讯文档 OAuth/MCP 和钉钉协议依赖仍保留独立许可证/授权门禁。
- 当前证据：聊天框真实“外部连接”按钮进入 `/capabilities?category=collaboration`，能力中心动态展示飞书、腾讯文档、微信、钉钉和失败关闭的 dsh-im 适配卡；分类级“配置外部连接”复用现有 History/`popstate` 进入 `/settings?section=connections`。主代理 Computer Use 看到飞书 App ID/Secret、腾讯文档 OAuth Token、钉钉 Client ID/Secret 的真实本机凭据表单。微信沿同一 loopback Connection RPC 生成真实 iLink 一次性二维码并轮询/取消，原始 QR token 仅在 Host 内存、扫码成功凭据只进入 Keychain/CurrentUser DPAPI；真实服务探针生成 3,168-byte PNG 后立即取消，未扫码或提交授权。Agent 的 `e_mate_qr_generate` 则独立复用目标 Tool、Job、Attachment 与 Image renderer 输出普通文本/URL PNG，不通过 GenUI 或第二 transport。授权前截图仍为 `../../artifacts/design-qa/S11-external-connections/settings-authorization-step-1280.png`。
- 退出：四类连接的发现、路由和授权前置步骤均以 provider 真实页面/挑战通过，日志和前端无凭据值；微信二维码必须来自真实 iLink 而非静态卡或假图，也不要求本版本扫码确认或完成真实授权。
- 依赖：S07、S10。

## S12 组合验收

- 输入：S00-S11 的单一发布候选 tarball、固定数据集、真实账号和 Computer Use 脚本。
- 修改边界：主进程执行验收；独立失败才交给子代最小修复，只有主进程关闭条目。
- 检查：安装/自然语言在线升级/快捷方式、身份/模型切换与上下文连续、弱网/上游恢复、usage、目标 Harness 原生消息流与 e-Mate 品牌扫描、图片画廊、内置能力与生图稳定并发上限、外部连接授权前 handoff、迁移、性能和负向边界。
- 退出：每个场景有日志、截图、Trace、产物、摘要与审计证据；无账号/授权项明确阻塞。
- 依赖：S00-S11。

## 唯一主 Goal 与恢复顺序

本版本只使用当前 Codex 任务中的一个主 Goal。不得为各切片创建竞争 Goal，也不设置人为 token budget。每次开始、恢复或上下文压缩后按以下顺序恢复事实：

1. 读取唯一主 Goal；
2. 读取 `git status --short`、分支、HEAD、Base/Profile 与目标平台；
3. 完整读取 `AGENTS.md`、`target-contract.md`、本文件及最新一条 `development-log.md`；
4. 核对当前切片的源码 diff、测试和回执；
5. 仅当 Goal、文档、HEAD 和工作区一致时继续。

优先级固定为：用户最新明确要求 ＞ `AGENTS.md` ＞ `target-contract.md` ＞ 本切片合同 ＞ `development-log.md` 的已验证事实 ＞ 实现。测试通过不能覆盖上层合同。

### S35 · 冻结、安装、更新、回滚与发布

- 本地、dirty、unpackaged、临时 Computer Use 与 loopback 候选只作为开发证据，必须使用隔离 user-data/DSH home 和 loopback/fixture 更新元数据；本地进程不得持有生产签名、R2、Feed、desired-state 或官网写权限，不得上传或激活任何线上用户可见更新。
- 正式发布只能消费 protected-main CI 的 exact admitted artifact set。local path、临时目录、symlink 组件、手工复制/重建字节、开发签名、fixture receipt 或 dirty source SHA 一律在首个生产写入前 fail-closed；本地更新测试结束后丢弃隔离状态，不能从测试命令继续进入生产上传/激活。
